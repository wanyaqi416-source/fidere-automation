# Fidere Client Test Design

本设计面向后续业务自动化阶段。当前阶段不新增业务自动化用例，只把 P0/P1/P2 测试点拆清楚。

## 分级原则

| 优先级 | 定义 |
| --- | --- |
| P0 | 不产生真实数据的核心可访问性、只读状态、提交前阻断；或业务流程的最低风险提交前校验 |
| P1 | 表单校验、筛选、详情页、确认页摘要；需要特定测试数据但不点击最终确认 |
| P2 | 完整提交、跨端审核、第三方回调、异常路径；必须有 Sandbox 和清理策略 |

## 入金 / 数字资产注入

| 优先级 | 测试点 | 数据/前置 | 自动化范围 |

| P2 | 链上或托管入账后流水出现在账户和交易页 | Sandbox 链/托管回调 | Client + 第三方/后台联动 |

## 兑换

| 优先级 | 测试点 | 数据/前置 | 自动化范围 |
| --- | --- | --- | --- |
| P0 | 首页总资产区 `兑换` 打开完整 `资产兑换` 弹层，并等待 `你卖出`、`你获得`、`获取报价` 出现 | 已登录客户端账号 | 客户端完全自动化 |

| P1 | 金额为空时 `获取报价` 禁用，金额有效后启用并进入报价摘要 | 有可兑换余额；金额控件填充方式需固定 | 客户端提交前停止 |
| P1 | 报价区域展示汇率、手续费、到账金额、报价时间 | 报价服务可用 | 客户端提交前停止 |

| P2 | 最终确认兑换，验证余额变化、`OTC-*` 业务编号和已完成交易流水 | 专用资金账号、Sandbox、单 worker、零重试、单次授权 | 客户端完全自动化，不依赖 Admin |

## 资金互转 / 券商资金划转

| P0 | 券商账户转信托：100 USD 显示 0 USD 手续费、100 USD 预计到账 | 已开通券商账号 | 已实现并通过；Decimal 校验 |
| P1 | 空金额、0、余额不足、最低/最高金额规则 | 可读取的账户余额和后端规则 | 空值/0/页面限额已探测；表单不显示余额，提交时规则待确认 |

| P0 | TR-003：法域账户转券商并由Admin通过，验证法域余额扣减与流水 | 法域余额充足、最低金额明确 | Pending；券商目标余额无直接Oracle |
| P1 | TR-004：券商账户转法域账户并由Admin通过，验证法域余额增加 | 券商余额人工确认 | Pending |
| P2 | TR-005：双向往返并验证最终法域余额与总手续费 | 两次独立唯一申请、低频授权 | Pending；不加入默认回归 |
