本计划基于当前测试账号登录后的真实客户端页面整理。本阶段只实现只读 Smoke，不执行入金、出金、兑换、开户、资金互转、理财认购等会改变账户余额或业务状态的操作。

## 场景分类

### 1. 客户端只读 Smoke

当前阶段已实现：

- 登录状态复用
- 客户端首页
- 一级菜单导航：仪表板、账户、交易、信托服务
- 投资入口可见性
- 未登录权限保护

### 2. 客户端页面基础回归

建议下一阶段实现：

- 仪表板核心卡片、资产分布表格和最近交易列表的只读结构校验
- 账户页资产分布与最近活动的只读结构校验
- 交易页筛选控件只读展开/收起校验，不提交筛选写操作
- 信托服务页文档中心 tab 的只读切换校验

### 3. 表单和异常校验

待实现。仅允许做不会提交业务状态的前端校验，例如必填项、格式提示、空搜索结果。

### 4. 会改变业务状态的客户端操作

暂不实现。未来必须使用 `@mutation` 或 `@money` 标签，并显式设置 `ALLOW_CLIENT_MUTATION_TESTS=true` 后才能运行。

### 5. 依赖管理端审核的跨端流程

暂不实现。本阶段不处理 Admin 或 `tests/workflows`。

### 6. 依赖银行、BaaS、邮件或其他第三方的流程

暂不实现。需要明确测试环境、测试账号、第三方沙箱和数据清理策略后再进入自动化。

## 自动化安全约束

- 每次 Client 测试命令由 Setup Project 自动登录一次并覆盖 `auth/client.json`；同一命令内的测试复用该最新状态，不在 `beforeEach` 重复登录。
- `npm run test:client` 和 `npm run test:client:smoke` 默认排除 `@mutation` 和 `@money`。
- Client fixture 会拒绝非测试环境 host。
- Client fixture 会阻止未显式设置 `ALLOW_CLIENT_MUTATION_TESTS=true` 的写操作测试。
- 报告、日志和附件不得主动输出账号、密码、验证码、Token、Cookie 或完整银行账号。
